1. Dataset Description

  I choose this Weather Forecast for a few reasons, besides it meeting
  the criteria for what is required for this final project. Back in my
  undergraduate, I did research on Glacial Mass Loss over time using
  LiDAR data, and wanted to do something within the same topic.
  Additionally, I always wanted to play around with weather forecast
  data to predict how the weather will be like. Afterall, it is
  important to know what the weather would be like before going out. As
  a Minnesotan, and with winter approaching, everyone will be checking
  the weather forecast every time they go out. Originally, I wanted to
  focus on storms and weather prediction against natural disasters, but
  couldn’t find a big enough dataset, so I stuck with the weather
  forecast. This all really started after watching a video on Waffle
  House and learning that they serve as a gauge index for FEMA.

  This dataset comes from operational logs of a real-world production
  weather forecasting system. Each record represents a forecast instance
  and includes features generated by climate and atmospheric models.
  These features capture various environmental conditions such as
  atmospheric pressure, cloud coverage, temperature estimates, humidity,
  precipitation, and other heterogeneous climate-related variables.

  The features set is a curated subset of the variables used in the
  Shift 1.0 Weather Forecasting Challenge (you can reference the paper
  on the kaggle site for more details). This refined selection provides
  meaningful climate indicators while maintaining a manageable level of
  complexity for forecasting and machine learning analysis.

  Kaggle: “Each instance in the Weather Forecasting dataset comes from
  logs of a production weather forecasting system. The features are from
  the climate models. The feature include climate preasure, cloud
  coverage, temperature estimates and more heterogeneous features. The
  list of features is a subset of the features used in the dataset from
  the shift 1.0 challenge (see the paper for details).”

2. Data Collection Approach

  To obtain and prepare the dataset for analysis, I explored several
  different approaches for collecting the Kaggle weather-forecasting
  data and transferring it into my AWS environment. My main objective
  was to move the dataset directly into an S3 bucket so it could be
  processed using Spark on EMR, much like the labs ran in class.

  Tools and Methods Used:

-   Kaggle CLI for authenticated dataset downloads

-   AWS S3 buckets for cloud storage

-   Cloud9 for running shell scripts and automation

-   Bash scripting (custom automation attempts)

-   Partial imitation of the EMR module from class (S3 bucket creation +
      cluster linking)

  Manual Upload to S3:

-   Downloading the dataset from Kaggle to my local Windows machine.

-   Uploading the files to S3 using the AWS Console.

-   Pros: Easy and guaranteed to work.

-   Cons: Not automated; inefficient for large datasets; defeats the
      purpose of a reproducible data pipeline.

Automated Kaggle → Cloud9 → S3 Pipeline:

  Workflow Plan:

1.  Install the Kaggle CLI directly in Cloud9.

2.  Authenticate with kaggle.json stored in ~/.kaggle/.

3.  Download the dataset using a bash script.

4.  Automatically unzip it.

5.  Automatically push the extracted files into an S3 bucket.

6.  (Optional) Link to an existing EMR cluster for processing.

  Pros:

-   Most automated

-   Fully reproducible

-   Ideal for big-data workflows

  Cons:

-   Requires IAM permissions Cloud9 users do not always have

-   Errors like NoCredentialsError, KeyError: "username”, ZIP file
      mismatch, and permission blocks

-   Debugging paths and permissions took significant time

EMR Lab Imitation

  EMR Lab Replication:

-   Creating new S3 buckets

-   Automatically creating EMR clusters

-   Automatically creating IAM roles

-   Running a full automated pipeline

  Pros:

-   Fully dynamic infrastructure

-   Mirrors real-world data engineering workflows

  Cons:

-   Not possible without IAM permissions

-   Resulted in multiple access-denied errors

-   Led to the script accidentally generating several buckets before
      failing

3. Data Preparation

  The data preparation involved inspecting the table and normalizing
  column names to ensure consistency across all features. I evaluated
  the dataset for missing values, invalid numeric entries, and
  duplicated rows. Several climate-related columns contained null or
  non-numeric values, so I applied a mean-imputation strategy and
  created indicator flags marking where imputations occurred. I also
  identified and removed duplicate records to avoid biasing the model.
  Numerical columns were then standardized, and outliers were detected
  using an IQR-based method and clipped to reduce the influence of
  extreme anomalies that could distort model training. I would like to
  note that I have only done this to the weather_preview.csv as the
  weather.parquet file often left to crash takes too long in its
  computation.

4. Data Analysis & Insights

  After preparing the dataset, I performed a series of exploratory and
  modeling tasks to understand climate relationships and identify
  meaningful weather patterns. The analysis began with descriptive
  statistics, correlation checks, and outlier exploration across all
  numeric features. I computed unique counts to distinguish
  categorical-like fields and generated a heatmap to visualize
  missing-value structure. From there, I ran regression models,
  including Linear Regression and Random Forest Regressor, to evaluate
  how well the available climate variables could predict temperature. I
  also performed unsupervised learning using K-Means clustering to group
  weather conditions into interpretable meteorological patterns. Several
  visualizations, such as correlation heatmaps, scatterplots with
  regression lines, and cluster plots, were produced to support
  interpretation.

 

5. Data Visualization

  I produced several visualizations using Matplotlib, Seabornm and
  Pandas-based plotting tools. These visualizations helped confirm
  relationships discovered statistically and revealed additional
  structure in the weather data. []

  One of the primary charts I created was a scatter plot with a
  regression line showing the relationship between atmospheric pressure
  and temperature. This visualization illustrated a surprising positive
  relationship between these variables, contrary to typical
  meteorological expectations, suggesting potential effects of elevation
  bias or missing contextual features in the dataset. It can also be due
  to not using the weather.parquet file. []

  Another key visualization was a cluster scatter plot generated from
  KMeans output, which displayed the four learned weather clusters in
  pressure temperature space. This chart made it easy to observe how
  different combinations of humidity, wind, and precipitation formed
  distinct weather regimes. These visualizations served as intuitive,
  high level summaries of complex multidimensional climate patterns.

 

6. Overall Reflection

  Working through this project provided a hands-on understanding of the
  full data engineering and analytics pipeline from ingestion to
  cleaning, modeling, and visualization. Several parts of the workflow
  went very well. Once the dataset was available locally, the data
  cleaning, preparation, and analysis stages were straightforward. Using
  Python, Pandas, and Scikit-learn allowed me to quickly standardize
  values, impute missing data, detect outliers, and run a variety of
  statistical and machine learning models. Visualization tools like
  Matplotlib and Seaborn also made it easy to explore relationships in
  the weather variables and communicate key insights.

  The most challenging part of the project was automating the movement
  of the raw dataset into S3 bucket. Properly configuring AWS
  credentials, IAM permissions, and the Cloud9 environment required
  extensive troubleshooting. Although the rest of the workflow was
  smooth, this early pipeline stage showed how critical access control
  and environment configuration are in real-world big data systems.

  Through this process, I gained a much deeper understanding of how big
  data pipelines operate, especially the importance of managing cloud
  permissions, storage paths, and region settings. I also learned the
  value of modularizing pipeline steps (ingest → clean → curate →
  analyze) so that failures in one stage do not halt progress in
  another. This project demonstrated tools like AWS S3, Cloud9, EMR,
  Spark, and Python integrated to support scalable analytics workflows.

  If I were to do this project again, I would dedicate more time early
  on to verifying AWS access roles and automating the S3 ingestion
  script in a more robust and fault-tolerant way. I would also consider
  using other tools, or at least looking at other tools. Additionally, I
  want to use the entire weather.parquet file instead of just the
  preview for analytics. Overall, the project strengthened my
  understanding of both the technical and operational challenges of big
  data environments and helped me develop a cleaner, more repeatable
  workflow for future analytics tasks.
